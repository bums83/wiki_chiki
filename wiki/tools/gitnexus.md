# GitNexus

`GitNexus` — это client-side code intelligence engine и knowledge graph creator для репозиториев. Он индексирует кодовую базу и строит graph-based представление связей между файлами, вызовами, зависимостями, кластерами и execution flow.

Практически это даёт не просто поиск по файлам, а архитектурный слой для работы с кодом: агент или человек видит, как компоненты связаны между собой, где проходит цепочка вызовов и какие участки системы зависят друг от друга.

## Два основных режима

У проекта два рабочих сценария:

1. **CLI + MCP** — локально индексируешь репозиторий и подключаешь AI-агентов через MCP.
2. **Web UI** — быстро открываешь репозиторий в браузере, смотришь graph view и общаешься с кодовой базой через чат.

Это удобно разделяет use case:
- CLI + MCP — для повседневной разработки и точной работы с кодом;
- Web UI — для исследования, демо и разовых разборов.

## Почему это полезно

GitNexus полезен там, где обычного текстового контекста уже мало.

Он помогает:
- не терять зависимости между модулями,
- видеть архитектуру целиком,
- уменьшать количество blind edits,
- давать маленьким моделям более полный контекст,
- ускорять code exploration в больших репозиториях.

По смыслу это близко к инструментам для agentic development, но с упором именно на граф знаний, а не на плоское резюме файлов.

## Bridge mode

Команда `gitnexus serve` связывает локально проиндексированные репозитории с веб-интерфейсом.

Это удобно, потому что:
- не нужно загружать код заново,
- не нужно переиндексировать один и тот же проект для браузерной работы,
- web UI может использовать уже подготовленный локальный индекс.

## Где он особенно уместен

GitNexus хорошо подходит для:
- крупных репозиториев с заметной архитектурной связностью,
- работы AI-агентов с кодовой базой,
- ревью и расследования чужого кода,
- задач, где важно быстро понять blast radius изменений,
- команд, которые хотят добавить к MCP не просто доступ к файлам, а структурированное понимание кода.

Внутри wiki его логично держать рядом с [MCPorter]({{ '/wiki/tools/mcporter' | relative_url }}), потому что оба инструмента работают с MCP-слоем, но GitNexus делает ставку на граф знаний и анализ репозитория.

С точки зрения workflow он также дополняет [Вайб-кодинг]({{ '/wiki/llm-agents/vibe-coding' | relative_url }}): если вайб-кодинг — это управление агентом через ограничения и контекст, то GitNexus добавляет к этому глубокую архитектурную видимость.

GitNexus особенно хорошо ложится на практики, описанные в [Agents.md]({{ '/wiki/llm-agents/agents-md' | relative_url }}): он помогает репозиторию стать более навигируемым для AI-агентов и поддерживает контекстные файлы уровня проекта.

## Ограничения

Важно учитывать и границы:

- для очень больших кодовых баз браузерный режим ограничен памятью, поэтому CLI остаётся более надёжным вариантом;
- качество анализа зависит от полноты индекса;
- лицензия OSS-версии не является permissive open source в классическом смысле, поэтому её нужно отдельно проверять перед коммерческим использованием.

## Практический вывод

`GitNexus` — сильный инструмент для случаев, когда агенту или разработчику нужен не просто доступ к исходникам, а структурированная модель репозитория.

Его главная ценность — в превращении кода в навигабельный knowledge graph, который помогает понимать архитектуру, связи и последствия изменений.
