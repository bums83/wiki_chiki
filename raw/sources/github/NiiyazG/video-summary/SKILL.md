# Генерация коротких видео-обзоров (Video Summary)

## Триггер
Пользователь: «сделай видео-обзор», «сгенерируй видео по [ссылке/тексту]», «сделай шортс по этой статье», «как NotebookLM, но в Hermes».

## Описание
Превращает текст/ссылку/PDF в вертикальное видео ~60 секунд с:
- Тёмным стилем (Dark Material)
- Крупными заголовками и тезисами на кадрах
- Плавной сменой кадров
- TTS-озвучкой (если доступен провайдер)
- Итоговым MP4 1080×1920 (вертикалка, 9:16)

## Зависимости

### Python
```bash
pip install --break-system-packages Pillow numpy requests
```

### Системные
- `ffmpeg` — сборка видео
- Шрифты: Ubuntu / DejaVu (уже есть в системе)

## Архитектура

```
Источник (текст/ссылка/PDF)
  → DeepSeek генерирует сценарий (JSON, каждая сцена с audio)
  → Скрипт рендера: Pillow рисует кадры (PNG, 1080×1920)
  → gTTS: для каждой сцены свой аудио-файл
  → FFmpeg: каждый кадр + его аудио → сегмент → concat → MP4
```
## Architecture decisions

### Почему Pillow, а не python-pptx?

Исходная идея: рендерить слайды через python-pptx, экспортировать в PNG через LibreOffice.

**Отклонено** потому что:
- LibreOffice не установлен на WSL (и его установка — ~500 MB + Java)
- Экспорт .pptx → PNG через LibreOffice headless даёт непредсказуемое качество
- Pillow даёт полный контроль над пикселями, не требует GUI, легковесен

**Когда вернуться к PPTX:** если понадобится экспорт в PowerPoint-формат (редактируемые слайды, а не видео).

### Почему concat demuxer, а не image sequence?

FFmpeg с `-framerate 1/N -i frame_%03d.png` требует явного перекодирования. `concat` demuxer с `duration N` даёт точный контроль над длительностью каждого кадра и чище работает с неравномерными duration.

## Сценарий (JSON-формат)

DeepSeek генерирует сценарий в таком JSON:

```json
{
  "title": "Заголовок видео",
  "scenes": [
    {
      "title": "Крупный заголовок",
      "bullets": ["Тезис 1", "Тезис 2", "Тезис 3"],
      "audio": "Текст этой сцены для озвучки"
    }
  ]
}
```

Рекомендации:
- 5–8 сцен
- Каждая сцена: заголовок (крупно) + 2–4 коротких тезиса
- Текст audio для каждой сцены: 1–2 коротких предложения (~15–25 слов), чтобы длительность была 6–10 сек на сцену
- Суммарно все audio: ~120–180 слов (60 сек видео)
- Пиши коротко, ёмко, без воды
- Каждый `audio` — грамматически законченная мысль (отдельный аудио-файл!)

## Стиль кадров (Dark Material)

```python
# Параметры рендера
WIDTH, HEIGHT = 1080, 1920  # Вертикальное видео 9:16
BG_COLOR = (13, 13, 15)     # #0D0D0F — почти чёрный
TITLE_COLOR = (100, 181, 246)  # #64B5F6 — голубой акцент
TEXT_COLOR = (255, 255, 255)   # белый
MUTED_COLOR = (112, 116, 120)  # #707478 — серый
ACCENT_LINE_COLOR = (100, 181, 246)  # акцентная линия
```

Компоновка кадра (1080×1920):
- Верх: нумерация сцены (`01 / 06`, 32px Light, Y=50)
- Заголовок: 64px Bold, отступ слева 80px, Y=320
- Макс 2 строки заголовка (28 символов), между строк 74px
- Акцентная линия: 80→220px (ширина 140px), высота 3px, отступ 16px от заголовка
- Тезисы: 44px Regular, отступ слева 80px
- Макс 4 тезиса по 2 строки (38 символов на строку)
- Между строками тезиса 52px, между тезисами 16px
- Check: text_y > HEIGHT-120 → break (не вылезает за край)
- Футер: 24px Light, Y=HEIGHT-70, отступ слева 80px — «© Гарипов Нияз Варисович t.me/ML_DS_one»

## TTS (обязательно для полноценного видео)

### gTTS (Google, работает из РФ)
```bash
pip install --break-system-packages gTTS
```
gTTS — приоритетный провайдер для РФ:
- Бесплатно, без ключа
- Русский язык поддерживается
- Не блокируется РКН

### Посценовая озвучка (критично!)
**НИКОГДА** не генерируй единый аудиофайл для всего сценария. Всегда делай отдельный аудио-файл для КАЖДОЙ сцены (`scene["audio"]` → отдельный mp3). Причина: единое аудио обрезается на последнем кадре (`-shortest`), и последняя сцена остаётся без звука.

Алгоритм:
1. Для каждой сцены: `gTTS(scene["audio"], lang='ru')` → отдельный mp3
2. Измерить длительность каждого аудио через `ffprobe`
3. Собрать сегмент: `ffmpeg -loop 1 -i frame.png -i audio.mp3 -t {audio_duration} -shortest seg_{N}.mp4`
4. Склеить все сегменты через concat demuxer

### Fallback-провайдеры (по порядку)
1. gTTS — основной для РФ
2. edge-tts — если gTTS недоступен (может не работать из РФ)
3. OpenAI TTS — если есть API-ключ

## Сборка FFmpeg (посценовая)

Каждый кадр собирается в отдельный сегмент с его аудио, затем сегменты склеиваются:

```bash
# Этап 1: для каждой сцены — сегмент (кадр + аудио)
ffmpeg -y -loop 1 -i frame_001.png -i audio_scene_01.mp3 \
  -c:v libx264 -pix_fmt yuv420p -t {dur} -r 30 \
  -vf "pad=ceil(iw/2)*2:ceil(ih/2)*2" \
  -c:a aac -shortest seg_001.mp4

# Этап 2: склейка всех сегментов
ffmpeg -y -f concat -safe 0 -i concat_list.txt \
  -c:v copy -c:a aac final_output.mp4

# concat_list.txt:
# file 'seg_001.mp4'
# file 'seg_002.mp4'
# ...
```

## Питфоллы

### 1. Pillow не поддерживает прозрачность шрифта
Не используй `font=ImageFont.truetype()` с несуществующими шрифтами — проверяй наличие через `os.path.exists()`.

### 2. FFmpeg падает на нечётных размерах
Pillow может создать кадр с нечётной шириной/высотой. H.264 требует чётные размеры. Используй `pad` фильтр в FFmpeg.

### 3. Длинные тезисы не влезают
Обрезай текст: максимум 40 символов на строку, 4 строки на сцену. Переноси по словам, используй `textwrap.fill()`.

### 4. TTS может отсутствовать
Всегда проверяй наличие TTS-провайдера. Если нет — предупреди пользователя и собери видео без звука.

**gTTS (рекомендуемый для РФ):** `pip install --break-system-packages gTTS`. Работает из РФ, бесплатно, русский голос. Приоритет: gTTS → edge-tts → OpenAI.

### 5. Аудио короче суммарной длительности кадров → последний слайд без звука

**Причина:** единый аудиофайл для всего сценария. FFmpeg с `-shortest` обрезает видео по длине аудио — последний кадр не доживает до конца своей озвучки.

**Фикс (реализован в gen_video_summary.py):**
1. Генерировать отдельный аудио-файл для КАЖДОЙ сцены (`scene["audio"]` → свой mp3 через gTTS)
2. Измерить длительность каждого через `ffprobe`
3. Собрать сегмент: `ffmpeg -loop 1 -i frame.png -i audio.mp3 -t {dur} -shortest seg_N.mp4`
4. Склеить все сегменты через concat demuxer

Проверка: у каждого сегмента длительность должна совпадать с его аудио. Если где-то `-shortest` обрезал — проблема в порядке аргументов FFmpeg.

### 6. DeepSeek может сгенерировать кривой JSON

В промпте строго указывай JSON-схему. При ошибке парсинга — ретрай с уточнением.

### 7. Вертикальное видео 9:16

Принудительно: 1080×1920. FFmpeg scale/pad фильтры при необходимости.

### 8. Ubuntu шрифты на WSL — симлинки с короткими именами

На WSL Ubuntu шрифты — симлинки: `Ubuntu-B.ttf` (Bold), `Ubuntu-R.ttf` (Regular), `Ubuntu-Th.ttf` (Thin). Оригиналы — вариативные с `[wdth,wght]` в имени (например `Ubuntu[wdth,wght].ttf`).

При поиске шрифта в `os.listdir()`:
```python
# Отсекаем квадратные скобки (вариативные имена)
f_lower = f.lower().split("[")[0]
if "bold" in f_lower or "b.ttf" in f_lower:
    ...
```

**Приоритет для заголовков:** DejaVu Sans Bold (читается крупнее и чётче вариативного Ubuntu) → Ubuntu Bold → любой другой bold.

### 8. Текст влезает не во все кадры — проверять на 4+ тезисах
При тестировании: сценарий с 4 тезисами по ~25 символов + заголовок в 2 строки. Если суммарная высота > HEIGHT-120, текст обрезается. Ставь запас по высоте: line_y + 60 + N×(52×строк + 16) < HEIGHT-120. Проверять на самой длинной сцене из сценария перед рендером.
